## 1. 快速认知

### 什么时候用 PAG

- 全屏或局部**光效、粒子、升级演出**（如 BigWin 链、背景 glow 循环）
- 需要与 **Spine 角色叠层**的特效（如转盘 Dragon 类演出）
- AE 时间轴复杂、用矢量/序列帧混合表达的动效

### 什么时候不用 PAG

- 纯静态 UI 图（用 FGUI 图片即可）
- **骨骼角色**且 Spine 已能胜任的动画
- 需要程序**频繁动态改大量文案**的界面（本项目文本替换能力有限，Editor 预览亦不支持完整文本替换）

### 和 Spine 的关系

```
FGUI 锚点组件（示例）
  ├── pagEffect (GLoader)   ← PAG 显示层
  └── holder (Graph)        ← Spine 3D 挂载点
```

- PAG 画在 `pagEffect` 上，Spine 挂在 `holder` 上
- **谁盖住谁**由 FGUI 编辑器里兄弟节点的**上下顺序**决定，改层级需 UI/程序协同
- 对齐参考：以 FGUI 里 `holder` 矩形为视觉对齐区域

### 怎么预览

| 阶段 | 工具 | 说明 |
|------|------|------|
| 制作中 | PAG Designer / 官方 PAG Viewer | 与 AE 源对比效果 |
| 进包前 | 同上 + 检查体积与合成尺寸 | 见第 4、5 章 |
| **最终验收** | **Android 真机** | 画质、透明、分段切换、同屏帧率以真机为准 |

> Unity Editor 内的 PagPreview（`Tools/PagPreview`）仅供程序开发参考，约 30fps，**不能替代真机验收**。

## 2. 工程目录与命名

### 目录结构（全项目）

各游戏 PAG 资源统一放在：

```text
Assets/GameRes/Games/<游戏名>/Pag/
  ├── 功能名.pag                 # 单次播放
  ├── 功能名_1024.pag            # 文件名体现合成档位（推荐）
  ├── BigWin/                    # 分段动画子目录
  │   ├── bigwin_start.pag
  │   └── bigwin_idle.pag
  └── Lopp/                      # 循环光效子目录
      └── glow_loop_720.pag
```

程序运行时从热更 AB 解压到设备 `PagCache/`，**路径与文件名必须与程序约定一致**。

### 命名约定

| 规则 | 示例 | 说明 |
|------|------|------|
| 小写 + 下划线 | `bigwin_start.pag` | 程序按字符串加载，**大小写敏感** |
| 后缀表尺寸档位 | `_720`、`_1024`、`_1920`、`_half`、`_full` | 便于识别合成规格 |
| `start` / `idle` 成对 | `bigwin_start` + `bigwin_idle` | 入场与循环分开导出 |
| 子目录表业务 | `BigWin/`、`Lopp/` | 同类资源分组 |
| **禁止** | 中文名、空格、特殊字符 | 避免 AB / Android 路径问题 |

### BigWin 六段链（1700 范例）

程序按顺序播放，**六段合成尺寸须一致**：

```text
BigWin/bigwin_start.pag
BigWin/bigwin_idle.pag
BigWin/supwin_start.pag
BigWin/supwin_idle.pag
BigWin/megawin_start.pag
BigWin/megawin_idle.pag
```

## 3. 合成尺寸规范

### 核心概念

**合成尺寸** = PAG 文件内的 `width × height`（在 PAG Viewer / 导出信息中查看）。

运行时默认按合成尺寸 **1:1 GPU 渲染**（原画档位）。程序侧可能按机型缩小渲染纹理，但**美术仍按目标档位交付原画**。

### 推荐档位（全项目统一）

| 档位 | 合成长边 | 适用场景 | 参考资源（1700） |
|------|----------|----------|------------------|
| 标清特效 | **720** | 局部 UI 特效、转盘、点缀类 | `Dragon.pag`（约 720×1281） |
| 标准弹窗 | **1024** | BigWin 主弹窗 | `BigWin_1024.pag`（**标杆**） |
| 全屏光效 | **1920** | 背景 glow；半屏/全屏用文件名区分 | `Lopp/glow_loop_720.pag` vs `glow_loop_half_1920.pag` |

### 硬性要求

1. **同一条业务链上的所有分段**（如 BigWin 六段）合成宽高**必须完全相同**，否则切 clip 可能出现闪屏
2. 合成画布**按实际可见区域**制作，不要无脑铺满 1920×1920
3. 竖屏机台：宽高比与机台设计分辨率一致（如 1080×1920 安全区），不需要的区域保持透明
4. 文件名中的 `_720` / `_1024` / `_1920` 应与文件内合成尺寸**一致**，避免误导程序与 QA

## 4. 制作与导出规范

> 工具：After Effects + PAG 导出插件，或 PAG Designer。不绑定具体版本号，以团队安装的官方工具为准。

### 时间轴

| 项目 | 建议 |
|------|------|
| 帧率 | 循环背景 **24～30 fps**；一次性演出 30 fps；**避免 60 fps 全长位图序列** |
| 循环段 | 首尾帧视觉一致；循环段单独导出为 `*_idle.pag` |
| 循环周期 | **时长 ≥ 1 秒**；循环总帧数须为帧率的**整数倍**（如 30 fps → 30/60/90 帧，即 1s/2s/3s），避免循环点跳帧 |
| 分段 | 入场 `*_start.pag` + 循环 `*_idle.pag` **分开两个文件** |
| 禁止 | 一个文件里既做完整入场又无限循环（程序难以精确控制） |

### 图层与效果

- **优先**：矢量形状 + 少量必要位图
- **控制**：位图序列张数、单帧分辨率、预合成嵌套层数
- **避免**：全屏高斯模糊、大面积噪点、过长无损序列
- **透明**：需透出 UI 的区域保持 Alpha；勿铺不透明底色

### 导出后自检（提交前必做）

- [ ] PAG Viewer 预览与 AE 源对比，无明显色差/裁切
- [ ] 记录 **width、height、duration（秒）、帧率**
- [ ] 文件体积符合第 5 章预算
- [ ] 分段链各文件合成尺寸一致
- [ ] 循环段：时长 ≥ 1s，总帧数为帧率整数倍，首尾衔接自然

## 5. 性能与体积预算

> 数据来源：**2026-07 Android 真机复测**（详见 `Tools/AndroidBuild/docs/PAG_PERF_RETEST.md`）。

### 单路播放

在当前播放框架下，单路 PAG 内容轻重对屏幕 FPS 影响较小（测试区 30 fps 配置下，轻/重资源均约 **30±2 FPS**）。

但**体积仍直接影响**：首次加载时间、内存占用、首帧卡顿、是否触发 OOM 保护。

### 同屏多路（美术必须关注）

多台 PAG **同时**播放时，按**合成档位**控制同屏路数（2026-07 团队约定）：

| 档位 | 合成长边 | 同屏上限 | 典型场景 |
|------|----------|----------|----------|
| 全屏光效 | **1920** | **1 路** | 过场、BigWin 全屏、Fade 类 |
| 弹窗 | **1024** | **3 路** | BigWin 弹窗、奖励面板 |
| 标清特效 | **720** | **4 路** | 转盘、局部光效、点缀 |

**混档同屏**（如 1 路全屏 + 多路弹窗）须策划/程序提前评审；**全屏档始终最多 1 路**。验收真机帧率 **≥ 25 FPS**。

| 指标 | 建议上限 | 1700 实测参考 |
|------|----------|---------------|
| 单文件体积 | **≤ 2 MB** 为佳；**> 8 MB 须评审并说明理由** | `BigWin_1024` ≈ 1.3 MB ✓；`XingXing2` ≈ 12.4 MB ✗ |
| 同屏组合 | 遵守上表分档上限；避免「全屏重位图 + 多路大特效」 | `Fade` + `glow_loop_720` 轻量组合可过 ✓；`Fade` + `XingXing2` 失败 ✗ |
| 循环光效边长 | 优先 **720 档** | `glow_loop_720` ≈ 369 KB vs `glow_loop_half_1920` ≈ 814 KB |

> **8 MB 红线**：程序在播放超大 PAG 前会主动卸载未用资源以防 OOM。超过 8 MB 的资源必须拆分或降采样，并在交付清单中注明。

### 标杆资源（对着做）

| 类型 | 路径（1700） | 说明 |
|------|-------------|------|
| 弹窗标杆 | `Pag/BigWin_1024.pag` | 体积与画质平衡 |
| 轻量循环 | `Pag/Fade.pag`、`Pag/Lopp/glow_loop_720.pag` | 背景循环优先参考 |
| 分段范例 | `Pag/BigWin/*.pag` | 六段 start/idle 链 |
| 转盘类 | `Pag/Dragon.pag` | 标清档位演出 |

### 反例（勿照搬）

| 文件 | 体积 | 问题 |
|------|------|------|
| `XingXing2.pag` | ≈ 12.4 MB | 位图过重，同屏灾难级掉帧 |
| `FeiZhou.pag` | ≈ 11.4 MB | 同上，须拆分或降分辨率 |
| `Fire.pag` | ≈ 5.1 MB | 超过 2 MB 建议线，需评审 |

## 6. 与 FGUI 的协作边界

### 程序依赖的 FGUI 结构

每个需要播 PAG 的 FGUI 锚点组件内，须有：

| 节点名 | 类型 | 要求 |
|--------|------|------|
| `pagEffect` | GLoader | 单槽位场景（如转盘） |
| `pagEffect1` … `pagEffectN` | GLoader | 多槽位测试/同屏场景 |
| `holder` / `holderN` | Graph | Spine 对照与对齐参考 |

GLoader 约定：

- 初始 `visible=false`
- `fill=scaleFree`
- 运行时由程序按 PAG 合成尺寸设置显示大小并铺满

### 美术 / UI / 程序分工

| 事项 | 负责人 |
|------|--------|
| 制作 `.pag` 文件 | 动效美术 |
| 新增 `pagEffect` 槽位、调整层级顺序 | UI（FGUI）+ 程序 |
| 绑定文件名、播放顺序、是否循环 | 程序 |
| 视觉对齐（与 holder 区域） | 美术提供标注 / 预览视频，UI 摆位 |

### 层级示意

```text
         ┌─────────────────────────┐
  上层   │  Spine（holder）         │  ← 角色、边框等
         ├─────────────────────────┤
  下层   │  PAG（pagEffect）        │  ← 光效、全屏闪白等
         └─────────────────────────┘
```

实际上下关系以 FGUI 编辑器中的节点顺序为准，**制作前与 UI 确认**。

### 仅交 .pag 不够的情况

- 新增同屏 PAG 路数 → 须 UI 加 GLoader + 程序绑槽
- 新 BigWin 分段链 → 须程序注册播放顺序数组
- Loading 需预热的文件 → 须程序加入预热列表

## 7. 交付流程

```text
1. 策划/程序提供需求单
   → 槽位用途、是否循环、是否分段、同屏方案、目标合成档位

2. 美术制作
   → AE / PAG Designer → 本地预览 → 自检（第 4 章）

3. 提交
   → .pag 文件放入约定目录
   → 填写附录 C 交付清单
   → 可选：附预览 mp4 方便评审

4. 程序接入
   → 进 GameRes/.../Pag/ → 打热更包
   → 必要时更新预热列表 / 播放序列

5. 验收
   → Android 真机按第 8 章清单执行
```

### 交付时须与程序确认（非美术独立完成）

- [ ] 新文件名是否加入 Loading 预热列表（`PagPathHelper.DefaultGamePagPreloadFiles`）
- [ ] 分段动画是否注册到业务播放序列（如 BigWin 数组）
- [ ] 同屏路数是否在程序侧有对应槽位绑定

## 8. 验收清单

### 目视项（美术可执行）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 画质 | 与 PAG Designer 预览一致，无明显锯齿/色偏 |
| 2 | 尺寸与对齐 | 在目标 holder 区域内对齐，无意外裁切 |
| 3 | 透明 | 非特效区域不遮挡 UI |
| 4 | 分段切换 | start → idle、BigWin 升级链切换时**无黑帧/闪一下** |
| 5 | 循环 | idle 循环无明显跳变或闪动 |
| 6 | 同屏 | 符合分档上限（1920×1 / 1024×3 / 720×4），真机 ≥25 FPS、无持续卡顿或发烫 |
| 7 | 体积 | 符合第 5 章预算；> 8 MB 已有评审记录 |
